# Popup 列表布局回归记录

## 现象

- 历史列表包含约 1900～2500 条内容时，点击设置按钮后，先显示部分“常规”内容，停顿一段时间后才完成设置面板展开。
- 日志中 `settings-click` 到 `settings-transition-run` 曾出现约 300ms 延迟；延迟发生在动画真正开始之前。
- 设置面板收起时需要保持原有文档流语义：列表先恢复，设置面板最后消失。

## 根因

设置面板使用文档流中的 `max-height` 过渡。高度逐帧变化会改变历史列表滚动容器的可视高度，并触发列表布局、滚动范围、滚动锚定和 sticky 日期标签更新。列表条目数量很大时，浏览器可能在动画开始前遍历较大的布局树。

## 已验证的错误修复方向

`d5fa1e6` 曾给 `.item` 添加：

```css
content-visibility: auto;
contain-intrinsic-size: auto 108px;
```

这会用固定 108px 作为离屏条目高度。条目的真实高度受标题换行、摘要、字体和内边距影响，进入视口后从估算高度切换为真实高度，导致列表整体位移。浏览器滚动锚定修正后的 `scrollTop` 又可能被保存并跨多次打开累积。

因此，以下方案禁止再次采用：

- 在正常滚动状态启用 `content-visibility: auto`；
- 使用未经逐条测量的固定 `contain-intrinsic-size`；
- 在设置开合时批量切换上述条目 CSS。

## 当前状态

已移除固定高度估算，条目漂移问题消失。设置面板也已恢复正常文档流；当前剩余问题是大列表下 `max-height` 过渡的布局延迟。

## 后续方案约束

后续修复必须同时满足：

1. 设置面板保持真实文档流推开列表；
2. 收起时列表先恢复、面板后消失；
3. 正常滚动使用真实条目几何，不引入固定高度估算；
4. 动画不能让 1900～2500 条历史项逐帧参与布局。

可优先验证：外层高度一次性改变，动画仅作用于设置内容的 `opacity`、`transform` 或 `clip-path` 等合成属性。
